## Findings

- 🔴 **I took the live prod stack down for ~14 minutes, via the pixel harness.**
  `.claude/skills/frontend-rewrite/harness/browser-guard.js:78` runs
  `execSync('docker compose up -d web --wait')` — a **bare** compose command from the repo
  root. On this host that resolves to project `tensies` (the directory name), which is the
  **live prod stack**, and it applies `docker-compose.yml` (dev), whose `web` publishes
  `127.0.0.1:8888`. Prod's nginx already holds 8888, so the recreated `tensies-web-1` failed
  to bind and was left in `Created` (exit 128, "port is already allocated"); `postgres` and
  `redis` were recreated with dev config at the same time. `:8888` served 502 from 23:35 to
  23:49.
  This fires **regardless of `TENSIES_URL`** — the globalSetup docker call ignores it — so
  pointing the harness at the design stack does not protect prod. It also swallows the
  failure: all 54 tests still ran and passed against 8890.
  **Recovery:** `docker compose -f docker-compose.prod.yml --env-file .env.prod up -d`,
  then `docker restart tensies-nginx-1`. The nginx restart is required and non-obvious —
  nginx was not itself recreated, so it kept the old web container's IP (172.18.0.5) and
  returned 502 to a perfectly healthy app on 172.18.0.6 until it re-resolved.
  **No data loss:** dev and prod both mount `tensies_pg_data`, and Postgres only seeds its
  password on first init, so the already-initialised cluster was unaffected.
  **Still armed.** `browser-guard.js` is unchanged. Anyone running the pixel harness on this
  host will do this again.

- 📝 **`loadProfile` has no negative cache** (`static/js/account-sync.js:32`) — pre-existing,
  unrelated to this change. On a non-OK response both `profileCache` and `profileFetch` end
  as `null`, so the guard at the top fails and every subsequent call re-fetches. Observed as
  ~198 identical `/api/profile/TestAlpha` 503s in a tight loop. Only manifests where
  `TELEMETRY_ENABLED=0` (`server/routes.py:378` returns 503 for profiles) — which is the
  design stack's own config, so it would be 200 and cached on dev/prod. The module comment
  already says it "degrades silently" for this case; it degrades *functionally*, just noisily.

- 📝 **The `/auth/login/options` 404 during sign-up is by design**, not a fault — the unified
  button tries `loginPasskey` first and falls back to `registerPasskey` on 404.

## Notes

- **The state machine behaved exactly as designed under every adversarial probe.** All six
  phases (`idle`, `shaking`, `awaitingServer`, `settling`, `revealing`, `celebrating`) were
  exercised on both clients, including the rare `awaitingServer` bounded-wait (5 samples on
  Alpha, 7 on Beta) — the path where the shake finishes before the server answers. It resolved
  via a frame every time; no `GIVE_UP` stranded a button.
- **Round-by-round overlay complementarity was perfect** across all 7 rounds: every round had
  exactly one `you took it` and one `taken by`, never two winners or two losers. Alpha took
  1/3/5, Beta took 2/4/6/7.
- **Pause-mid-reveal is worth recording as a positive.** Beta was in `settling` when the host
  paused; the frame was stashed by the `BROADCAST` edge, the reveal ran to completion
  (`revealing` 620 ms → `idle` 1450 ms), and the completion handler routed the stash through
  `showFor()` to the pause dialog — board still live underneath (9 dice), never bounced to
  loading. That is the documented invariant, reproduced end to end.
- The skill's Step 1 health check greps for uppercase `TENSIES`; the redesign changed the
  markup to `Tensies`, so the check reports FAIL against a perfectly healthy server.
- **The skill is stale vs. the Brass & Enamel redesign** (SKILL.md mtime 2026-08-07; redesign
  landed 2026-08-19/20). Selectors that have moved: the join screen is now a `#join-sheet`
  dialog on the landing rather than a `#join` screen; the game header carries the bare account
  mark, not a `.header-username` pill (so Step 27's pill assertion cannot pass); the
  round-result banner suffix reads `you took it` / `taken by`, not `Winner` / `Loser` (Step 22's
  parser needs updating). Preflight A calls for repairing the skill in place — deliberately not
  done here, to keep this run scoped to validating the refactor rather than rewriting the suite
  mid-flight.
- Steps 5/7 were run **after** the main game rather than inline, to avoid the throwaway-tab
  `localStorage` clobber the skill warns about corrupting Beta's session before the reconnect
  steps. Both were driven straight over the WS protocol instead of through a second tab.
- The design stack already sets `WEBAUTHN_RP_ID=localhost` / `WEBAUTHN_ORIGIN=http://localhost:8890`,
  so the auth steps needed **no container recreate** — the RP-swap hazard in Steps 24–29 does
  not apply when running against this stack.
