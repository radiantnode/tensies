## Findings

- **Pause-resume restamp fix — proven in the live flow.** The key bug this branch fixes: on pause-resume, `disconnected_at_ms` was never re-stamped, so a player who went offline during a long pause was dropped within one reaper sweep (~15s) instead of the documented 60s. Live timeline from the server logs: `pause 03:05:29 → resume 03:07:20 → Beta dropped 03:08:21` — **61s after resume**, exactly the restamped grace. Before resume, Beta's `disconnected_at_ms` was 88.7s stale; after resume it advanced ~100s to the resume moment. Without the fix Beta would have been reaped by ~03:07:35.
- **Roll pacing floor (0.75s) does not reject honest play.** The state-synced roll driver won a full round in 12 rolls with a minimum inter-roll gap of 1086ms — comfortably above the floor. A raw 120ms-apart double-roll (stripped-client simulation) still gets "Slow down" from the server (verified in the earlier per-fix check), and the button recovers unstuck via the new in-game error handler.
- **Prod asset refactor is sound.** The `FRONTEND_DIST` serving path was restructured (DevAssets for dev, `_render_index()`/`_page_template()` accessors) — prod still serves the single fingerprinted bundle, no modulepreload, immutable cache, and the document still flows through `SecurityHeadersMiddleware` (CSP present on the prod HTML). Bundled gameplay works.
- **Per-fix checks (outside the numbered suite), all green:** reaper `games:index` SREM + `restamp_disconnect` conditional + `try_end_paused` CAS unit-tested against live Redis; `legacy_pid` already-assigned guard verified against live Postgres (claimed-pid / account-UUID / fresh-pid cases); `/auth/*` rate limit verified with 20×404-then-429; 31 tsc errors → 0 with a new CI typecheck gate; dev asset edit reflected with no restart (hash changed, revert restored).

It self-corrected; `renderGame`'s `syncPaused` set it to "Roll" once the broadcast arrived. Not introduced by this branch (fanout timing is untouched).
